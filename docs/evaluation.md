# Workload manifests versus the thesis evaluation

`manifests/multi-run/` contains workload examples from the project's development. It is **not** an immutable export of the exact manifests used in the 2026 thesis experiment. Do not apply the whole directory expecting to reproduce the reported results: it contains an interactive Ollama Deployment as well as Jobs, and the current Job concurrency differs from the historical write-up. Every resource in these files must be reviewed before running it on a billable cloud cluster.

## What the thesis actually reports

- **Smoke test:** a CUDA `nbody` Pod was submitted with no cloud node ready; Cluster Autoscaler triggered a Verda GPU worker, the Pod finished with exit status 0, and autoscaler later deprovisioned the idle worker. This is a functional lifecycle observation, not a scale-up latency guarantee.
- **Heterogeneous run:** a single `2A100.44V` worker (two A100-SXM4-80GB GPUs), configured as `all-1g.10gb` MIG with seven slices per GPU. The workload mix comprised `nbody` (12 Job completions), GROMACS benchPEP (1), GROMACS benchMEM (2), ResNet-152 training (4), ViT-L/16 inference (1), one Ollama/Llama 3.1 8B serving workload, and CPU-only Pencil Code `conv-slab` (12 Job completions). The thesis calls these **21 GPU plus 12 CPU completions**, all successful in that test; technically this includes **20 GPU Job completions, one Ollama Deployment workload, and 12 CPU Job completions**. It did not test multi-node MPI throughput or compare runtime performance against the native on-premises environment.
- The thesis describes parallelism 4 for `nbody` and Pencil Code, and 2 for training. The current `nbody-simulation.yaml` and `pencil-code.yaml` use parallelism **2**, `ml-train.yaml` uses **3**, and `ml-inference.yaml` has **2** completions rather than the thesis's one inference run. These values have deliberately **not** been rewritten to historical settings: doing so would change concurrency, resource demand and potential cloud cost.

## Current manifest prerequisites and caveats

- Jobs generally target namespace `test` (create it separately if intended), zone `topology.kubernetes.io/zone=verda`, taint toleration `node-role.kubernetes.io/cloud=true:NoSchedule`, and instance type `2A100.44V`. The ML Jobs are **not** instance-type-portable without editing their selectors. Training reports VRAM but uses **fixed** batch sizes 64/8 intended for at least 16 GB; it has not been shown to fit the thesis's 10 GB MIG slices. Inference adapts batch sizes by VRAM tier. Each current ML Job executes both ResNet-152 and ViT-L/16 sequentially, unlike the thesis table's single-model labels.
- GPU Jobs request `nvidia.com/gpu: 1`. The thesis reports `nvidia.com/mig-1g.10gb` for its evaluated MIG node, while a future-work passage discusses advertising slices as `nvidia.com/gpu`. Separately, the **current Aalto ConfigMap** overrides the `2A100.44V` MIG template to **8** `nvidia.com/gpu` resources, not the thesis's **14** slices. Inspect the resource names actually exposed by GPU Operator and the provider's node templates before using these examples; this documentation does not assert that the checked-in Jobs schedule on a current MIG node.
- Some Jobs need `ngc-secret` to pull the NVIDIA container image; GROMACS manifests download benchmark inputs at runtime; inference loads pretrained model weights, which may require download; Ollama pulls its model; Pencil Code uses a separate GHCR image. Verify image availability, external network access, input integrity, storage/runtime assumptions, and job limits. A per-group `max_size` is a capacity ceiling, **not** a monetary budget.
- The thesis describes synthetic ImageNet-scale ML inputs, reduced model/batch settings, and a reduced GROMACS system. The checked-in benchPEP-h Job downloads a 12-million-atom input and should not be assumed to recreate that reduced system. The historical experiment was a single-node functional evaluation, not a performance tuning prescription or a production acceptance test.

The comments corrected in this PR describe the **current files**, not a claim that re-running them reproduces the thesis. Cluster-level or cloud validation was not performed.
